Merge strategy

Should merging happen in person?

  Depends on merge complexity:
  Simple merges (no conflicts, trivial changes): Either developer can merge alone.
  Complex merges (conflicts, architectural decisions, integration questions): Sit together.

Why in-person for complex merges:

  Resolve conceptual conflicts, not just textual ones
  Ensure both understand the integrated result
  Catch integration bugs immediately (e.g., you changed function signature, Lukas's code breaks)
