# lambdas

a lambda is C++'s syntax for a local procedure: an anonymous function
object defined inline, optionally capturing bindings from the enclosing
scope. see computation/local-procedures.md for the upstream concept.

syntax:
```cpp
[capture](params) -> return_type { body }
```
return type is deduced when omitted. params may be empty.


## capture

the capture clause specifies which bindings from the enclosing scope
enter the closure's environment, and how.

`[&]`  — capture all referenced bindings by reference.
         the closure holds pointers to the originals.
         mutations in the closure are visible in the enclosing scope.

`[=]`  — capture all referenced bindings by value.
         copies taken at definition time. mutations are local.

`[&x, y]` — mixed: x by reference, y by value. prefer explicit
             captures when the closure escapes the enclosing scope.

default captures (`[&]`, `[=]`) are convenient for short-lived local
procedures. explicit captures communicate intent and constrain risk.


## the type

each lambda has a unique, unnamed type generated by the compiler.
it is not `std::function`. `std::function` wraps any callable in a
type-erased container — it involves heap allocation and virtual
dispatch. use `auto` for local lambdas; `std::function` only when
type erasure is required (storing heterogeneous callables, passing
across ABI boundaries).

```cpp
auto f = [&]() { ... };   // zero overhead, inlineable
std::function<void()> g = f;  // type erasure, heap alloc
```


## memory risk: reference capture and lifetime

`[&]` makes the closure a borrower of the enclosing scope. if the
closure outlives that scope — stored in a member, returned, passed
to a thread — every captured reference dangles. the compiler does
not diagnose this.

rule: `[&]` is safe when the closure's lifetime is strictly contained
within the enclosing scope. for any closure that escapes: `[=]` or
explicit captures with ownership transfer (`move`).

```cpp
// safe: flush called and destroyed within the enclosing function
auto flush = [&]() { tokens_.push_back(...); };

// unsafe: lambda stored as a member, enclosing stack frame gone
this->callback_ = [&]() { use(local_var); }; // dangling ref
```


## `mutable`

lambdas are const by default: a value-captured binding cannot be
mutated in the body. `mutable` lifts this:

```cpp
int n = 0;
auto inc = [n]() mutable { return ++n; }; // mutates the copy
```

rarely needed. its presence is a signal that the closure carries
evolving state — consider whether a named struct would be clearer.
