m — not HTTP, nginx convention adopted by webserv.
HTTP itself has no concept of this unit. The Content-Length header carries a raw integer — bytes, no suffix, no unit marker. The m suffix exists purely in the config file language, which is an nginx-derived convention that your parser must interpret. In your grammar: size_suffix = "k" | "K" | "m" | "M" | "g" | "G". The parser reads 10m and converts it to 10 * 1024 * 1024 = 10,485,760 bytes, storing that integer in the ServerConfig or Location struct. The HTTP layer then compares Content-Length (a raw byte count from the request) against that stored integer. So m means mebibytes (MiB, base-2) in nginx; some implementations use megabytes (MB, base-10). For your implementation the team must decide and be consistent — nginx uses base-2, which is the correct choice.
