# Pushouts: The Categorical View of Merge

## Categories: Minimal Definition

A **category** C consists of:
- A collection of **objects**
- For each pair of objects A, B: a collection of **morphisms** (arrows) from A to B, written f: A → B
- For each object A: an **identity morphism** id_A: A → A
- **Composition**: given f: A → B and g: B → C, there exists g ∘ f: A → C

Satisfying:
- Associativity: h ∘ (g ∘ f) = (h ∘ g) ∘ f
- Identity: f ∘ id_A = f = id_B ∘ f

---

## Version Control as Category

Objects: Repository states (snapshots, trees, configurations)

Morphisms: Changes (patches, diffs, commits)

- Each commit represents a morphism from parent state to child state
- Identity: the empty change (no modification)
- Composition: applying changes sequentially

This framing makes the structure explicit.

---

## The Divergence Diagram

When two agents modify the same base state:

```
        B
       ↗
      f
     /
    A
     \
      g
       ↘
        C
```

A is the common ancestor.
f: A → B is one agent's changes.
g: A → C is another agent's changes.

We have a **span**: two morphisms sharing a common source.

The question: how do we complete this to unify B and C?

---

## Pushout: Definition

Given morphisms f: A → B and g: A → C, a **pushout** is:
- An object D
- Morphisms i: B → D and j: C → D
- Such that i ∘ f = j ∘ g (the diagram commutes)
- **Universal property**: for any other object E with morphisms i': B → E and j': C → E satisfying i' ∘ f = j' ∘ g, there exists a unique morphism u: D → E such that u ∘ i = i' and u ∘ j = j'.

```
        B
       ↗ ↘
      f   i
     /     \
    A       D
     \     /
      g   j
       ↘ ↗
        C
```

---

## Universal Property, Unpacked

D is the "smallest" or "most economical" object that B and C both map into.

"Smallest" means: any other such object factors through D. D contains exactly the information from both B and C, relative to A, and nothing more.

This is precisely what merge should do:
- Incorporate changes from B (relative to A)
- Incorporate changes from C (relative to A)
- Add nothing extraneous
- Produce canonical, unique result

---

## Why Pushouts Matter

If the category of states and changes has pushouts, then merge is:
- **Always defined**: for any divergence, a merge exists
- **Unique**: up to isomorphism, there's one right answer
- **Canonical**: not a matter of choice or strategy

Git's state category does NOT have all pushouts. When changes conflict (touch same region differently), no pushout exists. The system cannot produce D.

Conflict = failure of pushout to exist.

---

## Pullbacks: The Dual

The **pullback** is the categorical dual of pushout. Instead of completing a span, it completes a cospan:

```
        B
         ↘
          i
           \
    P → → → D
   ↙   j   ↗
  A       
         C
```

Given i: B → D and j: C → D, the pullback P is the "largest" object that maps into both B and C compatibly.

Pullback corresponds to: "find what's common" — the intersection perspective.
Pushout corresponds to: "find what's unified" — the union perspective.

LCA (least common ancestor) has pullback flavor: the most recent shared state.
Merge has pushout flavor: the minimal unified state.

---

## Colimits: Generalization

Pushout is a specific case of **colimit**.

A colimit is a universal construction that "glues together" a diagram of objects. Pushout glues two objects along a common base.

More complex merge scenarios (e.g., octopus merges — multiple branches simultaneously) correspond to more complex colimits.

---

## Computing Pushouts: The Problem

In Set (category of sets), pushouts exist and are computable: take disjoint union, then quotient by the equivalence relation generated by f(a) ~ g(a) for all a ∈ A.

In the category of text files? Less clear. What is the "quotient"? When changes conflict, the equivalence relation doesn't yield a coherent result.

Three-way merge algorithms attempt to compute pushouts. They succeed when changes are disjoint. They fail (conflict) when no pushout exists.

---

## Pijul's Approach

Pijul makes this categorical structure explicit:
- Patches are morphisms
- Repository states are objects
- Merge is pushout

When pushout doesn't exist (conflict), Pijul represents this as a special "conflict" state — essentially, the partial pushout with unresolved regions marked.

This makes conflicts first-class citizens rather than error conditions.

---

## Why This Matters

Thinking categorically reveals:
1. Merge is not arbitrary — it has universal property
2. Conflict is not bug — it's nonexistence of pushout
3. Different merge strategies are different approximations to the same ideal
4. The "right" merge, when it exists, is unique

Git's merge is ad-hoc engineering approximating categorical pushout. Understanding the ideal illuminates the approximation.
